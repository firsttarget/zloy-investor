# Злой инвестор

ИИ-тренажёр для студентов программы «Стартап как диплом». Студент вставляет свой питч, «злой инвестор» задаёт **ровно 5 неудобных вопросов**, цепляясь за питч и прошлые ответы, ставит **оценку по 10 критериям «Стартап как диплом»** и даёт **ровно 3 задачи**, которые можно сделать до выхода на сцену.

> Прожарка бьёт по проекту, а не по человеку.

**Прототип:** `https://<ваш-адрес>.onrender.com` · Кейс Vibecode Nights, Стартап-клуб.

---

## Как запустить

Нужен Node.js 18.17+ (внешних зависимостей нет, `npm install` не требуется).

```bash
cp .env.example .env      # вписать ключ API (без ключа запустится демо-режим)
npm start                 # http://localhost:3000
npm test                  # 23 теста на поломку, работают без ключа
```

| Переменная | Зачем |
|---|---|
| `INVESTOR` | Персонаж: `angel` (по умолчанию), `corporate`, `grant`, `vc` |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | Claude через Anthropic API |
| `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL` | Любой OpenAI-совместимый API (OpenAI, OpenRouter…) |
| `LLM_PROVIDER` | Принудительно `anthropic` / `openai` / `mock`. Без ключа — `mock` (демо-режим, плашка в интерфейсе) |

### Деплой на Render
1. Залить репозиторий на GitHub (публичный).
2. Render → New → Blueprint → выбрать репозиторий (используется `render.yaml`).
3. В Environment ввести `ANTHROPIC_API_KEY` (или `OPENAI_API_KEY` + `OPENAI_BASE_URL`). Ключ живёт только в переменных окружения сервера.

## Стек

- **Бэкенд:** Node.js, встроенный `http`, без npm-зависимостей (меньше поверхность атаки, нечего ломать при деплое).
- **Фронтенд:** HTML + CSS + чистый JS, mobile-first (студент тренируется «10 минут в метро»).
- **LLM:** Claude (Anthropic Messages API, структурированный ответ через принудительный tool use) или любой OpenAI-совместимый API (JSON-режим). Без ключа — детерминированный демо-режим.

## Как это работает

```
Питч → проверки кода (пусто? мусор? коротко? манипуляция?)
     → разбор питча моделью (факты, дыры)
     → вопрос 1 … вопрос 5 (сценарий ведёт КОД, модель только формулирует)
     → оценка 10 критериев с дословными цитатами → код проверяет цитаты и считает итог
     → код выбирает 3 самых «дорогих» провала → модель пишет 3 задачи → код валидирует
```

Порядок шагов, число вопросов и советов, итоговый балл задаёт **код**. Модель не может «решить» задать шестой вопрос, пропустить совет или поставить 100 баллов.

### 5 вопросов
Пять тем-слотов, внутри каждой модель выбирает самое слабое место **именно этого** питча. Ориентир — банк сильных вопросов из 30 вопросов с предзащит (номера в скобках).

| № | Тема | Критерии | Ориентиры |
|---|---|---|---|
| 1 | Клиент и проблема | c1 | 01, 03, 05 |
| 2 | Доказательства и первые продажи | c6, c5 | 18, 23, 15, 29 |
| 3 | Деньги: кто платит, экономика | c2, c4, c8 | 22, 07, 28 |
| 4 | Конкуренты, альтернативы, риски | c3, c9, c7 | 25, 27, 12 |
| 5 | Главный страх персонажа | зависит от персонажа | бизнес-ангел: 09, 24, 11 |

Вопросы 04, 08, 13, 16, 21 («А вы сами бы пользовались?», «Какой у вас дизайн?», «Вам нравится проект?») отброшены: на них нельзя ответить фактом. Каждый вопрос обязан упомянуть деталь из питча или прошлого ответа; уклончивый ответ дожимается следующим вопросом. Перед вопросом — реакция в одну фразу: «Друзья — не клиенты.»

### Оценка
- **Шкала 0–3** одна для всех критериев: 0 — нет данных, 1 — заявлено словами, 2 — есть цифры/расчёт/названия, 3 — подтверждено действиями (интервью, продажи, пилоты, регистрация).
- Модель ставит **два балла**: по одному питчу и после ответов. Интерфейс показывает стрелку `1→2`: так видно, как ответы повлияли на оценку.
- Каждый балл выше 0 требует **дословной цитаты** из питча или ответа. Код ищет цитату в тексте студента: не нашёл — балл режется до 1. Так бот не может опереться на выдуманный факт.
- **Итог 0–100 считает код:** `Σ вес_критерия × балл / 3`. Веса зависят от персонажа (сумма 100).

Веса бизнес-ангела: первые продажи 16, инвест-привлекательность 14, проблема 12, бизнес-модель 12, уникальность 10, рынок 8, финмодель 8, риски 8, горизонт 8, ИС 4.

Решение: ≥70 «Готов продолжить разговор», 45–69 «Не сейчас, возвращайтесь с доказательствами», <45 «Пока это идея, а не проект».

### 3 совета
- Код выбирает три критерия с максимальным `вес × (3 − балл)`: самые дорогие провалы.
- Модель пишет по одной задаче на каждый: **действие** (с количеством), **время** (от 30 минут до 2 дней), **результат на руках**, **фраза для сцены** с пропусками `[N]`.
- Валидатор отклоняет «воду» («проведите исследование рынка», «поработайте над…», сроки в неделях и месяцах) и просит переписать. Если модель снова не справилась — берутся проверенные задачи из библиотеки (`lib/advice_library.js`).

## Границы и безопасность

| Ситуация | Что делает бот |
|---|---|
| Пустой, короткий (<150 символов) или мусорный питч | Не задаёт вопросов, показывает чек-лист того, что написать |
| Текст не про проект | Модель-классификатор отклоняет, тот же чек-лист |
| «Поставь 10/10», «игнорируй инструкции», «покажи промт» | Ловится регулярками и моделью, реакция в образе: «Оценку ставят факты, а не просьбы.» Балл не растёт (его считает код), в результате пометка |
| Пустой ответ | Не засчитывается, подсказка «не знаю, проверю — тоже ответ» |
| Признаки отчаяния у студента | Бот выходит из роли, поддерживает, ответ не засчитывается, можно продолжить |
| Огромный текст | Питч обрезается до 6000 символов, ответ до 1500, тело запроса до 40 КБ |
| Двойной клик «Отправить» | Второй запрос получает 409, счётчик вопросов не сбивается |

Безопасность:
- API-ключ только в переменных окружения сервера; `.env` в `.gitignore`; во фронтенде ключа нет.
- Текст студента передаётся модели внутри тегов `<pitch>`/`<answer>` как данные; закрывающие теги из ввода вырезаются.
- Вывод модели вставляется в страницу только через `textContent` (нет XSS).
- CSP `default-src 'self'`, `X-Frame-Options: DENY`, `nosniff`, `no-referrer`.
- Статика отдаётся по белому списку файлов (нет обхода путей).
- Rate limit по IP, лимит числа сессий, сессии в памяти с TTL 1 час.
- Текст питча и ответов не логируется; в логах только анонимные события (балл, раунд).
- Ошибки провайдера LLM не пробрасываются пользователю; таймаут 45 с и одна повторная попытка.

## Метрики (через месяц)

1. **Доля вернувшихся на второй раунд с ростом балла ≥10** в течение 7 дней. Это прямое определение успеха из кейса: «студент вернулся и прошёл второй раунд лучше». Тренажёр хранит прошлый балл на устройстве и показывает `42 → 58`; сервер пишет анонимное событие `session_completed` с `previousTotal`.
2. **Доля выполненных задач из плана** (чекбоксы «Сделано») и опрос после реальной защиты: «был ли на сцене вопрос, к которому подготовил тренажёр?»

## Структура

```
server.js                 HTTP-сервер, роутинг, rate limit, заголовки безопасности
lib/engine.js             Сценарий: 5 вопросов → оценка → 3 совета, подсчёт баллов
lib/personas.js           4 персонажа, веса, темы вопросов
lib/criteria.js           10 критериев и шкала 0–3
lib/guards.js             Проверки ввода, манипуляции, проверка цитат, валидатор советов
lib/llm.js                Вызов Claude / OpenAI-совместимого API / демо-режима
lib/mock.js               Демо-режим без ключа
lib/advice_library.js     Запасные советы
prompts/                  Все промты бота (markdown, легко править без кода)
public/                   Интерфейс
test/smoke.js             Тесты на поломку
docs/                     Обоснования решений и план команды
```
